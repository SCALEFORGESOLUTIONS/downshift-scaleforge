The moment this is for

Someone watches it and says the second sentence is wrong.

On a one-shot tool that sentence costs a whole new generation, and the rest of the video comes back different too — new drawings, new timing, new things to check. So the fix gets skipped, or the video quietly goes out of date, or nobody makes the video at all.

Sketchie treats the video as the thing it actually is: a document that was compiled. Scenes are addressable. Correcting one is a small edit to one part, not a re-roll of the whole artifact.

What comes back

An MP4, and the document it was drawn from.

Every generation returns two things. The rendered video, and the scene graph: an ordered list of scenes, each with a heading, its narration, and elements bound to the exact narration word that reveals them. That binding is why a correction can be surgical. 

// the shape, from Sketchie's open eval schema
{
  "scenes": [
    {
      "id": "s2",
      "heading": "The resolver asks around",
      "narration": "Your resolver walks the chain…",
      "elements": [
        { "id": "e1", "type": "icon",
          "x": 120, "y": 180,
          "revealWord": "resolver" },
        { "id": "e2", "type": "arrow",
          "revealWord": "chain" }
      ]
    }
  ]
}

The schema, revealWord semantics and the mechanical checks are published under MIT at Downshift/explainer-evals.

Edit a field, or just say what is wrong

Open the scene list, change the heading, narration, labels or icon styling. When fields are not enough, describe the change in plain language — in the app, or as one instruction to the API.

Every edit is a version

A re-render appends a new version to the same explainer rather than replacing it, and you can point the head back at an earlier ready version. Nothing is overwritten in place.

The first edit of each video is free

Editing never consumes one of your two free videos, and the first re-render of each video costs nothing. Later ones draw a few seconds of minutes rather than a whole new video.

Not a manifesto, a gate

The generator obeys a spec you can read.

Sketchie publishes eleven design laws drawn from the published research on learning from video, each with its effect size and a link to the primary source, and turns them into numeric targets the pipeline is checked against. Every claim carries its own evidence grade, including the ones marked as unverified working assumptions. A sample:

Why six minutes is a ceiling and not a limit

Sketchie's spec cites Guo et al. (2014, Learning@Scale), an analysis of 6.9 million edX sessions, which reports engagement near 1.0 under six minutes, around 0.55 at nine to twelve, and roughly 0.2 past twelve. Longer material becomes a chaptered series instead of one long video.

That finding is about learning from video in general. It is not a measurement of Sketchie's own videos, and no such measurement exists. Read the paper.

The mechanical gate is open source

Layer A runs on the scene graph before any money is spent on voice or rendering: duration ceiling, per-scene band, element count, reveal words that resolve, the post-scene silence, the question-and-recap ending. A graph that fails is sent back with its failures fed into the prompt. That layer is MIT licensed and runnable.

Downshift/explainer-evals — schema, Layer-A checks and a worked passing example. Layers B and C are described on the site but not published.

Feed it what you already wrote

A plain prompt, or a PDF, Word file, PowerPoint, TXT or Markdown. Document mode follows your source instead of writing a generic script over the top of it.

Six narrators, previewable

Nora, Miles, Dean, Clara, Piper and Wren. Nora narrates by default. Every catalog voice speaks every supported language, so a course keeps one consistent narrator. Preview each before you generate.

Three shapes, thirty-second steps

16:9, 9:16 and 1:1. Set length in 30-second steps up to six minutes, or leave it on automatic and let the material decide.

For people wiring it into something

One POST in. Video and scene graph out.

Creation is asynchronous: the API returns 202 with a queued record, and you either poll it or hold open a Server-Sent Events stream and catch every status transition as it happens. When the record is ready it carries the MP4 URL and the graph.

The edit endpoint takes a plain-language instruction and re-renders only the scenes it touches, appending a version. There is a revert endpoint for pointing the head back. Generation endpoints are limited to 20 requests a minute; everything else shares 200.

API access requires a paid plan. Check the pricing page for the current tier and how API generations are metered — the site states these differently in different places, so confirm before you budget. There is also an MCP server, five tools, running as a local stdio process for Claude Code and Claude Desktop; a hosted connector for Claude web and mobile is on the roadmap, not shipped. A TypeScript SDK and a CLI are documented. 

curl -X POST https://sketchie.ai/api/v1/explainer \
  -H "Authorization: Bearer sk_..." \
  -H "Content-Type: application/json" \
  -d '{ "input": "Explain how DNS resolves a domain name",
        "length": "0:30" }'

→ 202 Accepted  { "status": "queued", … }

curl -X POST .../v1/explainer/{id}/edit \
  -d '{ "instruction": "Make scene 2 shorter and warmer" }'

→ 202 Accepted  new version, scene 2 only
